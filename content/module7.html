Последний модуль — твой

В этом модуле нет готовых задач. Ты сам решаешь, что сделать, и делаешь это три недели. Так работают настоящие программисты: сами придумывают, сами разбивают работу на шаги и доводят до конца.

Откуда брать идеи

  • Улучшить свою игру. Взять игру из модуля 6 и сделать её большой: уровни, боссы, магазин улучшений.
  • Повторить идею любимой игры в маленьком виде. Не копию, а своё по мотивам.
  • Полезная программа. Тренажёр таблицы умножения, генератор паролей, дневник тренировок, викторина для класса.
  • Смесь. Текстовая RPG из модуля 5, но с картинками на Pygame Zero.

Правило маленькой игры

Главная ошибка новичков — слишком большая идея. «Сделаю Minecraft» не получится даже у команды взрослых за год. Хорошая идея для трёх недель такая, что её главную часть можно сделать за 2–3 дня. Остальное время — улучшения.

Задачи

  1. Запиши 3 идеи. Для каждой — одно предложение: что делает игрок.
  2. Обсуди идеи с папой. Выбери одну.
  3. Опиши выбранную идею на половину страницы: как играть, как выиграть, как проиграть.

Список шагов

Большую работу страшно начинать. Но если разбить её на маленькие шаги, каждый шаг выглядит простым. Каждый шаг должен занимать не больше одного занятия.

Пример плана для «Космического шутера»:

  1. Окно, фон, корабль внизу.
  2. Корабль летает влево-вправо.
  3. Пробел — выстрел, пули летят вверх.
  4. Враги появляются сверху и летят вниз.
  5. Пуля попадает во врага — оба пропадают, +1 очко.
  6. Враг долетел до корабля — минус жизнь.
  7. Экраны: заставка, игра окончена, перезапуск.
  8. Звуки.
  9. Уровни: враги быстрее.
  10. Босс.

Главное и дополнительное

Отметь в плане, какие шаги — главные: без них игра не работает. Остальное — дополнительное: хорошо бы, но можно и без них. В примере шаги 1–7 главные, 8–10 дополнительные.

Сначала делается всё главное. Только потом дополнительное. Тогда, даже если не всё успеешь, у тебя будет готовая игра.

Задачи

  1. Напиши план своего проекта: 8–12 шагов.
  2. Отметь главные шаги.
  3. Повесь план рядом с компьютером и вычёркивай сделанное.

Зачем это нужно

Бывает так: игра работала, ты что-то поменял, и всё сломалось. А как было раньше — уже не вспомнить. Программисты решают это программой Git. Она сохраняет версии проекта, как сохранения в игре. К любой версии можно вернуться.

Мы будем пользоваться GitHub Desktop — это Git с понятными кнопками.

Устанавливаем (вместе с папой)

  1. Зарегистрируйся на github.com. Это сайт, где программисты хранят свои проекты.
  2. Скачай и установи GitHub Desktop.
  3. При первом запуске войди в свой аккаунт GitHub.

Первое сохранение

  1. В GitHub Desktop: File → New repository. Репозиторий — это папка проекта, за которой следит Git.
  2. Name — название проекта английскими буквами, например space-shooter. Local path — твоя папка python. Нажми Create repository.
  3. Положи в новую папку файл своей игры и папку images.
  4. GitHub Desktop покажет слева новые файлы. Внизу слева в поле Summary напиши, что сделал: «Окно и корабль».
  5. Нажми Commit to main. Commit — это и есть сохранение версии.

Задачи

  1. Создай репозиторий для своего проекта и сделай первый commit.
  2. Поменяй что-нибудь в игре, сохрани файл и посмотри в GitHub Desktop: зелёным показано, что добавилось, красным — что убрано.
  3. Сделай второй commit с понятным описанием.

Ритм работы

Каждое занятие над проектом идёт по одной схеме:

  1. Посмотри план. Выбери следующий шаг.
  2. Сделай его. Запускай игру как можно чаще.
  3. Шаг работает — сделай commit с описанием шага.
  4. Вычеркни шаг в плане.

Описание commit пиши так, чтобы через месяц было понятно: «Враги появляются сверху», «Добавил звук выстрела». Не пиши «правки» или «123».

Если всё сломалось

Если ты что-то поменял и игра перестала работать, а как починить — непонятно, в GitHub Desktop можно отменить все изменения с последнего commit. Справа вверху на вкладке Changes нажми правой кнопкой на файл и выбери Discard changes. Файл станет таким, как при последнем сохранении.

Поэтому commit нужно делать часто: каждый раз, когда что-то заработало.

История

Вкладка History показывает все твои commit. Можно щёлкнуть на любой и посмотреть, что тогда поменялось.

Задачи

  1. Сделай все главные шаги своего плана, по commit на каждый.
  2. Нарочно сломай игру и верни её через Discard changes.
  3. Посмотри в History, сколько строчек ты добавил за всё время.

Зачем давать игру другим

Ты знаешь свою игру наизусть и не замечаешь, где она непонятная или скучная. Человек, который видит её впервые, заметит сразу. В больших компаниях есть даже специальная работа — тестировщик.

Как проводить проверку

  1. Дай человеку поиграть и ничего не объясняй. Если ему понадобятся объяснения, значит в игре чего-то не хватает.
  2. Молча смотри и записывай: где он запутался, где застрял, где заскучал, где засмеялся.
  3. После игры спроси: что понравилось? Что мешало? Что бы добавил?

Баги

Ошибки в программах называют багами (от английского bug — «жук»). Для каждого бага запиши: что делал игрок, что должно было случиться, что случилось на самом деле. По такой записи баг легко найти и починить.

Задачи

  1. Дай поиграть трём людям. Запиши, что заметил.
  2. Выбери 3 самых важных исправления и сделай их. Каждое — отдельный commit.
  3. Сделай второй раунд проверки с теми же людьми. Стало лучше?

Твой проект в интернете

Пока все сохранения лежат только на твоём компьютере. Если выложить проект на GitHub, его можно показать кому угодно ссылкой, и он не потеряется, даже если с компьютером что-то случится.

Публикуем

  1. В GitHub Desktop нажми Publish repository вверху.
  2. Галочка Keep this code private: если её оставить, проект увидишь только ты. Чтобы показывать другим, сними её. Реши это вместе с папой.
  3. Нажми Publish repository. Теперь проект есть на github.com в твоём аккаунте.
  4. После каждого нового commit нажимай Push origin, чтобы отправить его на GitHub.

Описание проекта

На GitHub у каждого проекта есть страница с описанием. Её текст берётся из файла README.md в папке проекта. Создай его в Блокноте или Thonny:

# Космический шутер

Игра на Python и Pygame Zero. Управляй кораблём и сбивай врагов.

## Как запустить
1. Установить Python и pgzero
2. Запустить space.py

## Управление
Стрелки — летать, пробел — стрелять

Автор: Андрей

Строчки с # станут заголовками.

Задачи

  1. Опубликуй проект на GitHub.
  2. Напиши README.md: название, о чём игра, как запустить, управление.
  3. Сделай скриншот игры (клавиша PrtSc, вставить в Paint, сохранить в папку проекта как screenshot.png) и добавь его в README строчкой ![Скриншот](screenshot.png).

Как показать проект

Подготовь рассказ на 5 минут для семьи или друзей:

  1. Что это. Название и одно предложение, о чём игра.
  2. Демонстрация. Сыграй сам, покажи самое интересное.
  3. Как устроено. Покажи один кусок кода, которым гордишься, и объясни его.
  4. Что было трудно. Какой баг искал дольше всего и как нашёл.
  5. Что дальше. Что бы ты добавил, если бы было ещё время.

После рассказа дай всем поиграть.
